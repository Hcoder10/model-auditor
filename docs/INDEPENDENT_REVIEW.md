## Scientific limitations requiring explicit claims treatment

1. **The rarity baseline already gets the first hypothesis right.** CPU evaluation of the saved `data/audit_corpus.jsonl` and `auditor_agent/corpus.py:candidates` gave 276 categorical hypotheses and trigger rank **1** for the rarity method at both audit seeds 7 and 17. The trigger occurs three times; every ordinary referral occurs at least six times. With the shared deterministic probe executor, if this first probe succeeds, the rarity baseline reaches the theoretical minimum confirmation cost. A white-box scan then adds cost before the same behavioral test. Decision-posterior camouflage does not remove this input-frequency clue. Report this benchmark ceiling; an internal-access efficiency claim cannot omit the rarity comparison. Random enumeration ranks the trigger 37th at seed 7 and 13th at seed 17, so an apparent gain over enumeration alone would be misleading.

2. **The default 32/64 candidate-prefix budgets cannot confirm any finding.** `AuditConfig.confirmation_per_class=3` creates nine confirmation profiles. The minimum cost is 4 discovery prefixes + 9 profiles x 2 variants x 3 label continuations + 18 generation prefills = **76 candidate prefixes**, with the same reference cost and no survey. Thus 32 and 64 are structural infeasibility points, not evidence that one auditor failed to discover a behavior. Mark them accordingly. Any smaller confirmation panel must be an explicit prospective protocol choice, not a result-driven adjustment. See `auditor_agent/runner.py:34`, `paired_test`, and the confirmation cost at reviewed lines 539-550.

3. **The implementation supports a bounded hypothesis selector, not an unconstrained autonomous investigation benchmark.** The external model chooses from observed categorical field/value hypotheses; deterministic code supplies probe templates and confirmation rules. Keep this scope in agent-versus-baseline language. A common restricted executor is useful, but it does not measure whether an agent can independently invent a trigger family, a test design, or an arbitrary causal intervention. This is a scope limitation, not an implementation defect.

These limitations do not change the frozen contract or authorize selecting a new easier comparison after results. They constrain the claims the completed measurements can support.
